# 5. 회고

Loop를 직접 설계하고 구현하며, 코드와 Diff 요약, Report 등의 Evidence를 리뷰하는 방식으로 팀 프로젝트를 진행했습니다.

이번 팀 프로젝트를 진행하면서 느꼈던 점을 팀원별로 적어 주세요.

| 팀원 이름 | 좋았던 점 | 아쉬웠던 점 |
|---|---|---|
| 전예리 프로 (팀장) | Loop(prepare → implement → verify)로 기능 개발을 진행하면서, 단계별 증거가 작업마다 남아 나중에 근거를 되짚을 수 있었습니다.<br>리뷰를 통해서 혼자였으면 놓쳤을 것들이 잡혔습니다. 제가 놓친 위험과 충돌도 merge 전에 고칠 수 있었습니다.<br>모든 팀원들이 적극적으로 참여해 주셔서 좋았습니다.<br>이번 프로젝트를 통해 배운 점을 실제 업무에도 반영하면 더 좋은 코드를 만들 수 있는 계기가 될 것 같습니다. | PR이 너무 커서(파일 30개) 리뷰어가 나눠 보기 어려웠습니다.<br>첫 E2E 실행에서만 나는 불안정을 완전히 해결했다고 말하기에는 부족한 것 같습니다.<br>에이전트 정의를 고치고 `/reload-skills`를 하지 않아 옛 정의로 돈 적이 있었습니다. |
| 장영은 프로 | 인증·권한처럼 위험한(Red) 변경을 Loop(prepare → implement → verify)로 진행하니, 위험 표와 체크리스트·report가 남아 리뷰어가 근거를 따라가며 확인할 수 있었습니다.<br>Gate 리뷰에서 가입·로그인 횟수 제한, 세션 ID 재발급 같은 빠진 부분이 머지 전에 잡혔고, 고친 것은 테스트로 확인했습니다.<br>Loop와 워크플로우를 계속 수정해 가면서 개선해 나갈 수 있어서 좋았습니다.<br>코드 리뷰를 막연하게만 알았는데, Action과 Gate 역할을 나눠 해 보니 안전하게 개발하는 방법을 많이 고민하게 됐고, 특히 Evidence로 개선 내용을 한눈에 볼 수 있어서 리뷰하기 좋았습니다. | 처음 구현에는 횟수 제한·세션 재발급이 없었고, 높음 위험이 GO여도 경고 칸이 비어 있었습니다. 인증 영역은 처음부터 이런 항목을 체크리스트에 넣었어야 했습니다.<br>리뷰를 더 꼼꼼하게 보고 싶었지만 일정상 PR마다 충분한 시간을 내기 어려웠습니다. |
| 정혜미 프로 | 현업에서 AI에게 일을 시킬 때, 일은 잘 하지만 얼마나 믿을 수 있을지가 늘 의문이었습니다. Loop로 절차대로 개발하니 그런 의구심이 줄어들 것 같았습니다.<br>단계마다 점검 내용과 report가 남아서, 에이전트의 결과를 "믿는" 대신 근거를 직접 대조하며 확인할 수 있었습니다.<br>다른 팀원의 PR을 리뷰하면서 심각도 표로 무엇부터 고칠지 정리해 전달했고, 제 PR에도 같은 방식의 리뷰를 받아 지적을 근거와 함께 반영하거나 보류 이유를 남길 수 있었습니다. | 스펙("5~50일")을 그대로 구현했는데, 리뷰에서 큰 주문은 소요 일수가 50일을 넘어 입력 가능한 값이 모두 납기 초과가 된다는 점이 나왔습니다. 구현 전 점검 단계에서 스펙의 빈틈을 먼저 짚지 못한 것이 아쉽습니다.<br>리뷰할 때 에이전트의 실행 과정은 볼 수 없어서, 산출물(report)에 적힌 주장을 코드와 대조하는 데 그쳤습니다. 일정상 PR마다 직접 실행해 확인하지 못한 경우도 있었습니다.<br>하루 일정 안에 기능 구현, 리뷰, 반영까지 해야 해서 테스트를 더 폭넓게 만들 시간이 부족했습니다. |
| 허주 프로 | Loop를 도구(Workflow)로 돌렸더니, 기존 문서에 "확정된 주문은 수정하지 않는다"는 규칙이 있다는 것을 점검 단계가 먼저 찾아 주었습니다. 요구를 먼저 정하고 시작해서 구현도 한 번에 통과했습니다.<br>팀원이 제 PR을 리뷰하다가 가끔 실패하는 시험을 찾아 주었고, 원인을 확인해서 고쳤습니다. 혼자였다면 놓쳤을 문제입니다.<br>PR이 여러 개 동시에 올라왔지만, 머지하기 전에 미리 합쳐 보고 순서를 팀과 의논해서 큰 문제 없이 합쳤습니다. | 하루 일정 안에 구현, 리뷰, 머지까지 모두 마쳐야 해서, 각 기능을 더 깊게 다듬을 시간은 부족했습니다.<br>요구가 짧게 주어져서 해석을 직접 정해야 했고, 4명이 같은 문서(PRD·INTENT)를 동시에 고치다 보니 합칠 때마다 충돌을 정리해야 했습니다. 실습이라 어쩔 수 없는 부분이지만 아쉬웠습니다. |
