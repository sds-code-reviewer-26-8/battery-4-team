# basic-explain

코드를 처음 보는 사람이 **적은 에너지로, 단계별로** 프로젝트를 이해하고, 나중에 코드 리뷰를 편하게 할 수 있도록 **설명용 웹 문서(HTML)** 를 만든다. 인자는 받지 않는다.

## 대상 독자
- 코드를 처음 보며, 이해에 많은 에너지를 쓸 수 없다.
- 개발 지식이 없다. 중학생도 따라올 수 있어야 한다.

## 절차

1. **프로젝트 파악.** 아래를 읽고 "무슨 일을 하는 프로그램인가"를 업무 관점으로 정리한다.
   - `CLAUDE.md`, `README*` 같은 기존 문서
   - 빌드 파일, 진입점, 핵심 도메인 로직과 규칙, 데이터 흐름
   - 테스트 코드(규칙을 가장 정확하게 보여 준다)
   - 숫자와 규칙은 **코드에서 확인한 값만** 쓴다. 확인하지 못한 것은 쓰지 않는다.
2. **`docs/understand/정혜미/basic_guide.html` 작성.** 이미 있으면 먼저 읽고 구조와 스타일을 이어받아 갱신한다. 폴더가 없으면 만든다.
3. **브라우저로 연다.** 파일을 다 쓴 뒤 기본 브라우저로 띄운다.
   - Windows: `Start-Process docs/understand/정혜미/basic_guide.html` (PowerShell) 또는 `start "" docs/understand/정혜미/basic_guide.html`
   - macOS: `open docs/understand/정혜미/basic_guide.html`
   - Linux: `xdg-open docs/understand/정혜미/basic_guide.html`
4. **보고.** 만든 파일 경로, 탭 3개의 제목, 인터랙티브 기능 목록, 확인하지 못한 부분(있다면)을 짧게 알린다. 브라우저에서 직접 동작을 확인하지 못했다면 그렇게 말한다.

## 문서 규칙

**형식**
- 외부 라이브러리와 네트워크 없이 열리는 **단일 HTML 파일**(CSS·JS 인라인).
- 화면은 한국어. 라이트/다크 모드(`prefers-color-scheme`)와 좁은 화면(모바일 폭)에서도 읽혀야 한다.
- 탭은 `role="tablist"` / `tab` / `tabpanel`과 `aria-selected`를 쓰고, 좌우 화살표 키로 이동할 수 있게 한다.

**내용: 정확히 3개 탭, 이해 단계 순서**
1. **무슨 프로그램인가요?** — 누가 어떤 문제를 풀려고 쓰는가, 큰 흐름(입력→처리→결과)을 단계로 보여 준다. 자주 나오는 용어는 쉬운 말로 풀이한다.
2. **어떻게 움직이나요?** — 핵심 규칙 한두 가지를 골라 직접 만져 보며 이해하게 한다. 실제 동작을 단순화했다면 그 사실을 화면에 적는다.
3. **고르고, 확정하고, 관리해요** 형태의 마무리 탭 — 결과를 고르거나 확정하고 상태를 관리하는 흐름, 그리고 실수나 충돌을 막는 안전장치를 설명한다. 프로젝트 성격에 맞게 제목은 바꿔도 된다.

**인터랙티브 (탭마다 최소 1개)**
- 눌러서 단계를 넘기기, 슬라이더·선택 상자로 값 바꾸기, 하루씩 진행하는 시뮬레이션, 규칙을 어기면 막히는 체험 등.
- 입력값을 바꾸면 결과가 즉시 바뀌어야 하고, 처음으로 되돌리는 버튼이 있어야 한다.

**금지**
- 코드 용어(클래스, 함수, 엔티티, API, 트랜잭션, 낙관적 락 등)와 파일·패키지 이름을 본문에 쓰지 않는다. 필요한 개념은 일상어로 풀어 쓴다.
- 코드에서 확인하지 못한 숫자·규칙·계산 결과를 지어내지 않는다.
- 이 스킬은 `docs/understand/정혜미/basic_guide.html` 외의 소스 코드를 수정하지 않는다.

## 완료 기준
- `docs/understand/정혜미/basic_guide.html`이 존재하고 탭이 정확히 3개이며, 각 탭에 인터랙티브 요소가 있다.
- 본문에 개발 용어가 없다.
- 브라우저로 열었다.
