1한눈에 보기 — 세 단계에서 한 일

1Prepare

  • 취소 후 뒤로 가기를 하면 삭제된 주문 상세가 다시 열려 Whitelabel 오류 화면이 뜨는 문제를 재현으로 확인했다.
  • PRD 에 뒤로 가기를 직접 적은 문장이 없다(문서 공백). 취소 전 목록에 취소한 주문 행이 남아 보일 수 있다(이번 범위 밖).
  • order-detail.js 한 줄 수정, E2E 1개 추가, 체크리스트 3개(재현 해소·재발 방지 테스트·Regression 전체).

2Implement

  • 취소 성공 후 이동을 location.href 에서 location.replace(previousList()) 로 바꿨다.
  • 파일 2개: 스크립트 1줄(+주석 1줄), E2E 테스트 1개.

2체크리스트 3개 결과

1
재현 절차(목록 → 상세 → 취소 → 뒤로 가기)에서 삭제된 주문 상세와 오류 화면이 열리지 않는다. 충족
근거: 별도 포트 8095·별도 DB 로 띄운 앱에서 새 E2E(e2e031-041.spec.ts 224행)를 실행해 통과. goBack 후 URL 이 /orders/{id} 가 아니고 Whitelabel Error Page 가 없음을 확인했다.
2
재발 방지 E2E 가 있고 통과한다. 수정 전에는 실패했다. 충족
근거: 테스트는 URL 과 오류 화면 문구를 직접 검증한다(상태 코드만 보는 약한 검증 아님). 수정 전 코드(HEAD worktree, 포트 8096)에서 같은 테스트가 실패했다: 기대 not /orders/1, 실제 http://localhost:8096/orders/1. 수정 후 통과. 새 테스트는 1개뿐이다.
3
기존 JUnit 과 E2E 전체가 기대대로다. 다른 결함의 test.fail() 은 그대로 실패한다. 충족
근거: ./gradlew test --rerun-tasks: 24건 통과. E2E 전체 48건 기대한 결과: 취소 이동·필터 유지·성공 안내 테스트 통과, test.fail() 인 E2E-035, E2E-013b 는 그대로 실패(예상 실패). 첫 실행에서는 E2E-021 이 간헐 실패했으나 단독 실행과 전체 재실행에서 통과했다.

6남은 이슈 · 확인하지 못한 것

  • PRD 7장에 뒤로 가기 동작 한 문장 추가 여부는 사용자가 정한다(이번 범위에서 문서는 수정하지 않음).

  • 첫 E2E 전체 실행에서 E2E-021 이 한 번 실패했다(목록 행 셀을 읽지 못함). 단독 실행과 전체 재실행에서 통과했고 이번 변경과 무관해 간헐 실패로 판단한다. 원인은 확인하지 못했다.
