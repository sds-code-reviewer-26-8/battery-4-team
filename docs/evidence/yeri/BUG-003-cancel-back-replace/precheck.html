배경 · 사용자가 어떤 상황인가 이해함

주문 목록에서 상세로 들어가 취소하면 목록으로 이동한다. 이때 브라우저 뒤로 가기를 누르면 삭제된 주문 상세가 다시 열려 오류 화면이 뜬다.

근거

요청 문구, 재현 결과(/orders/1 에서 Whitelabel Error Page), order-detail.js 81행, PRD 7장

목적 · 왜 필요한가 이해함

취소 뒤 뒤로 가기를 눌러도 삭제된 주문 상세로 돌아가지 않는다. 취소 직후 이동·필터 유지·안내 한 번 표시는 그대로다.

근거

PRD 7장, INTENT 5.6·원칙 8, 요청 문구(location.replace 적용)

3규모와 위험

변경 규모 (여러 계층, 많은 파일, DB 변경, 핵심 규칙 변경, 되돌리기 어려움 → 큼)

작음중간큼

사용자가 이 규모·위험을 알고 있는가: 해당 없음 — 큰 변경이 아니라 확인이 필요 없음(파일 1개 1행, 요청도 "빠르게")

위험심각도대응
취소 경로의 이동 방식만 바뀐다. 취소 후 뒤로 가기가 상세 이전 목록(취소 전 모습)으로 간다.낮음새 E2E 로 뒤로 가기 결과를 고정하고 E2E-033·BUG-002·DEV-001 테스트로 이동·필터·안내를 확인한다.
뒤로 간 오래된 목록에 취소한 주문 행이 남아 있을 수 있다. 그 행을 누르면 삭제된 주문 상세 오류(INTENT 9장 3번 계열)가 난다.낮음이번 범위 밖으로 기록만 한다.

가정 (확인하지 못한 것)

  • 요청은 location.replace('/orders') 로 적었지만, BUG-002 의 필터 유지(PRD 7장)를 깨지 않도록 location.replace(previousList()) 로 적용한다고 가정한다.
  • 뒤로 가기 시 브라우저의 오래된 목록 복원(bfcache) 동작은 확인하지 못함.
