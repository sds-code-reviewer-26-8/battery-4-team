이유

  • 배경·목적 이해: 요청의 두 제안(쿼리/sessionStorage, 목록 이동 후 1회 안내)이 같은 목표이며 코드로 확인함. order-detail.js 취소 분기가 res.message 를 쓰지 않고 이동함.

배경 · 사용자가 어떤 상황인가 이해함

주문 상세에서 취소하면 아무 안내 없이 주문 목록으로 이동해(order-detail.js) 사용자가 취소가 성공했는지 알기 어렵다. 다른 상태 변경은 같은 화면에 성공 문구가 뜬다.

근거

요청 문구. src/main/resources/static/js/order-detail.js 취소 분기가 location.href='/orders' 후 return 하며 서버가 준 res.message 를 쓰지 않음. PRD 7장 "취소 직후에는 이전 페이지(주문 목록)로 이동한다".

목적 · 왜 필요한가 이해함

취소가 끝나 목록에 도착하면 "상태를 '취소'(으)로 바꿨습니다" 안내가 한 번 보이고, 새로고침하거나 다시 들어오면 사라진다. 사용자가 성공 여부를 바로 알 수 있다.

근거

요청 문구("목록에 안내 1회 표시"). INTENT 원칙 8·9의 방향(결과를 조용히 넘기지 않음). 기존 .alert.ok 스타일(app.css)과 서버 메시지(OrderController 92행)를 재사용.

안내가 남아 다음 방문에 다시 뜨는 경우(1회 표시 위반)낮음목록에서 읽자마자 지운다. 새로고침 후 사라짐을 테스트로 확인.
