1한눈에 보기 — 세 단계에서 한 일

1Prepare

  • admin/admin 단일 계정에 회원 가입과 가입 회원 로그인을 더하고, 가입 회원은 admin과 같은 권한을 갖게 한다.
  • 공개 가입이라 누구나 전 기능을 쓰게 됨(위험 높음), 회원 테이블 추가, PRD 10장·INTENT 원칙 14와 충돌해 문서 갱신 포함.
  • 문서 수정, Member 엔티티, MemberService, API·화면, 테스트 순서. 체크리스트는 가입·로그인, 동일 권한·이력, 접근 통제·해시 저장 3개.

2Implement

  • PBKDF2 해시 저장 회원 가입, /signup 화면, 로그인에서 회원 인정.
  • 신규 파일 5개 포함 계층별 변경, 문서 2개.
  • JUnit과 login-access E2E 통과.

3Verify

  • 체크리스트 3개 모두 충족(직접 재실행).
  • JUnit 17/17, E2E login-access 6/6 통과.
  • 사람 확인 필요 항목 있음(남은 이슈 참조).

2체크리스트 3개 결과

1
가입 후 로그인 성공, 중복/예약 아이디/짧은 비밀번호는 이유와 함께 거부, 기존 admin/admin 로그인 유지 충족
근거: OrderFlowTests signupThenLoginWorksAndAdminStillWorks, signupRejectsInvalidInputWithReasons 통과(15/15), E2E-042 통과.
2

근거: memberHasSameAccessAsAdminAndIsRecordedInHistory 통과, history[1].changedBy가 tester04인지 단언(OrderFlowTests.java 141줄).
3
비로그인 접근 통제 유지(signup 외 화면은 /login 리다이렉트, API 401)이고 비밀번호가 평문이 아닌 해시로 저장됨 충족
근거: E2E-001~005 통과, signupDoesNotOpenOtherPages와 passwordIsStoredAsSaltedHash 통과. WebConfig 제외 경로는 signup 3개만 추가(git diff 확인).
