사용자 추가기능 / 회원 가입 후 로그인, 가입 회원은 admin과 동일한 권한

날짜 2026-10-22 00:00:00회차 1작성 prepare 에이전트브랜치 feature/signup · 커밋 f38632f요청자 youngeun로그 없음

1판단

GO: 회원 가입 + 가입 회원 로그인 추가. 가입 회원은 역할 구분 없이 로그인한 사용자와 같은 권한(= admin과 동일). PRD 10장·INTENT 원칙 14와 충돌하므로 문서를 먼저 고친다.

주의

  • 구현 후 결과 확인: 필요 — 회원 테이블 추가(DB 스키마 변경)와 핵심 불변식(원칙 14 로그인 통제) 관련 코드 변경

이유

  • 요청이 명시적: 회원 가입 후 로그인, 가입 회원 = admin 권한. 현재 로그인은 하드코딩 admin/admin 1개뿐이다 (AuthController.ACCOUNT). 배경·목적 이해함.
  • 문서 충돌(사용자가 문서 변경을 의도한 요청으로 판단): PRD 3장 "현재는 로그인 계정이 하나뿐", PRD 10장 "계정 관리와 역할별 권한, 보안 요건 제외", INTENT 원칙 14·7장 "고정 계정 1개", INTENT 4장 "권한 체계 등 범위 확장을 섞지 않는다. 필요하면 먼저 PRD에 반영". 계정 추가 기능을 명시 요청했으므로 의도적 범위 변경으로 보고 PRD·INTENT를 함께 고친다.
  • "admin과 동일한 권한"은 PRD 3장 "역할별 권한 없음, 로그인한 누구나 모든 기능"과 이미 같다. 역할·권한 체계는 새로 만들지 않는다(최소 범위). 인터셉터는 세션 로그인 여부만 보므로 권한 코드 변경은 없다.
  • INTENT 8.3 "로그인을 실제 인증으로 바꿀 때": 이력의 "누가"는 문자열로 유지하고 로그인 구현에 직접 묶지 않는다. 가입 아이디를 세션 loginUser 문자열로 그대로 쓰면 만족한다.
  • DB에 회원 테이블이 추가되므로(ddl-auto=update) 구현 후 사람의 결과 확인이 필요하다.

배경 · 사용자가 어떤 상황인가 이해함

현재 로그인은 admin/admin 고정 계정 1개뿐이다. 담당자가 직접 가입해 로그인할 수 있게 하고, 가입자도 지금의 admin과 같이 모든 기능을 쓰게 한다.

근거

요청문; AuthController.java ACCOUNT="admin"; LoginInterceptor.java; PRD 3장·10장; INTENT 원칙 14

목적 · 왜 필요한가 이해함

끝나면 가입 화면에서 아이디·비밀번호로 가입하고, 그 계정으로 로그인해 주문·마스터 기능을 admin과 똑같이 쓸 수 있다. 기존 admin/admin 로그인은 계속 동작한다.

근거

요청문 "회원 가입 후 로그인, 가입 회원은 admin과 동일한 권한"; PRD 3장 역할별 권한 없음

3규모와 위험

변경 규모 (여러 계층, 많은 파일, DB 변경, 핵심 규칙 변경, 되돌리기 어려움 → 큼)

작음중간큼

사용자가 이 규모·위험을 알고 있는가: 예 — "사용자 추가기능 / 회원 가입 후 로그인"은 PRD가 범위 밖으로 둔 계정 관리를 직접 요청한 것

위험심각도대응
회원 테이블 신규 추가(DB 스키마 변경, 개발 DB ./data/battery 영향)중간새 엔티티만 추가하고 기존 테이블은 건드리지 않음. ddl-auto=update가 처리. 되돌리기는 테이블 삭제로 가능.
비밀번호 평문 저장·보안 (PRD 10장: CSRF 등 보안 요건은 범위 밖)중간비밀번호는 솔트+해시(JDK 표준 PBKDF2, 새 의존성 없음)로 저장. CSRF·잠금 등은 범위 밖 유지.
누구나 가입하면 admin급 권한을 얻음(공개 가입 = 전 기능 개방)높음요청이 명시한 동작이라 구현하되 PRD/INTENT에 명기하고 report에서 사람이 확인.
/api/signup, /signup 이 로그인 인터셉터를 거치지 않아야 함(R11·원칙 14 완화 위험)중간제외 경로는 signup 관련으로만 한정. E2E-001~005 접근 통제 회귀 확인.
아이디 중복, admin 아이디 선점(사칭)중간아이디 unique + "admin" 가입 거부, 입력 검증은 한 번에 알림(원칙 7·8).

가정 (확인하지 못한 것)

  • 가입 즉시 로그인하지 않고 로그인 화면으로 이동하는 방식으로 가정(가입 후 로그인).
  • 아이디/비밀번호 규칙(예: 아이디 3~20자 영숫자, 비밀번호 4자 이상)은 요청에 없어 임의로 정한다.
  • 승인·이메일 인증 없는 즉시 가입으로 가정.
  • 기존 E2E의 admin/admin 로그인 사용은 유지된다고 가정.
