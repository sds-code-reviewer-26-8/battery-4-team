Thymeleaf 서버 렌더링 화면을 정적 HTML과 JavaScript(데이터는 JSON API 호출)로 바꾸고, 사용자에게 보이는 동작과 화면 주소는 그대로 유지한다.

1한눈에 보기 — 세 단계에서 한 일

1Prepare

  • 서버가 템플릿 6개로 그리던 화면을 정적 HTML+JS로, 폼 POST를 JSON API로 옮기되 보이는 동작은 같게 한다. 기준선은 JUnit 23건, E2E 45건(42 통과 + 예상 실패 3건).
  • 큰 변경(약 25~30개 파일), 인증 경로(정적 HTML도 비로그인이면 /login), 동시 변경 보호(version을 JS가 보관), 비동기 렌더링 간헐 실패 위험.
  • 단계 8개 계획. 체크리스트: 불변 동작, 안전망 기준선 동일(2회 연속), 알려진 결함 보존과 Thymeleaf 제거.

2Implement

  • 정적 HTML 5개와 JS 5개, JSON API(로그인·목록·상세·상태 변경·마스터), PageController(화면 주소를 HTML로 forward)를 추가하고 Thymeleaf를 제거했다.
  • 템플릿 6개 삭제, 컨트롤러 4개 수정·1개 삭제·1개 신규, 설정·빌드·테스트·문서 포함. DB·엔티티·업무 규칙 코드는 불변.
  • JUnit 24건 통과, 전체 E2E 45건 2회 연속 통과, 기존 설정 021~030도 10건 통과.

3Verify

  • 체크리스트 3개 모두 충족.
  • JUnit 24/24, E2E 45/45 기대한 결과(2회 연속, 예상 실패 3건 유지).
  • 알려진 결함 3건은 별도 버그수정 Loop로 이월. 수정 전 코드에서의 신규 단언 실패 확인은 못 함.

★리팩토링 결과

  • 동작이 그대로임을 확인한 방법: JUnit 24건과 E2E 45건(001~041)을 격리 포트·메모리 DB에서 2회 연속 실행해 모두 기대한 결과. 바뀌면 안 되는 목록(비로그인 302/401, 로그인 문구, 목록·상세·마스터 문구, 상태 변경 안내, 마스터 전부 아니면 전무)은 E2E와 JUnit 단언으로 확인.
  • 정리한 것: 서버 렌더링을 정적 HTML+JS와 JSON API로 분리하고 폼 POST·모델 렌더링·Thymeleaf 의존성을 제거했다. 화면 주소·문구·클래스는 그대로.
  • 손대지 않은 것: 알려진 결함 수정(취소 직후 500, 없는 주문 번호 500, E2E-013b), 업무 규칙·DB 변경, CSS·애니메이션 로직 변경, HELP.md의 Thymeleaf 언급.
