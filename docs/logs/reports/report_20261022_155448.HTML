1Prepare

  • 총 비용에 공장 운영비가 빠져 있어 마스터 설정, 계산, 화면, 스냅샷에 추가하는 새 기능으로 판단했다.
  • 여러 계층과 DB 컬럼 추가를 건드리는 큰 변경(사용자 승인). 기존 DB 보정이 가장 위험.

  • 운영비 = 하루 운영비 x 운영 일수, 총비용 최소 안(운항비+운영비 최소), 마스터 입력과 검증, 4항목 화면.
  • 소스 약 9개 파일(계산, 엔티티, 서비스, JS 4개, html), 테스트 파일, 문서 2개.

  • 만든 것: 공장별 하루 운영비 마스터 입력(억 원, 기본 10억, 0 초과 1,000억 이하), 운영비 계산과 총비용 최소 안, 안마다 생산 원가·운항비·운영비·총 비용 표시, 공장별 운영 일수·운영비 표, 두 안이 같을 때 한 줄 안내, 확정 주문 스냅샷, 기존 주문 '없음' 표시, 기존 DB의 빈 운영비 10억 보정.

6남은 이슈 · 확인하지 못한 것

  • 첫 E2E 실행에서만 한 건씩 실패하던 E2E-021(목록·요약이 그려지기 전에 읽음)과 E2E-032(취소 후 앱의 이동과 테스트의 page.goto가 겹침)는 테스트 쪽 대기 부족으로 확인했고(응답 지연·반복 실행으로 재현), 대기를 보강했다. 보강 뒤 두 테스트를 5번씩 반복해 15개 통과, 전체 E2E를 연속 2번 돌려 모두 통과했다. 반복 수가 적어 불안정이 완전히 사라졌는지는 추가 관찰이 필요하다. 새 JUnit 테스트의 수정 전 실패는 새 규칙을 일부러 깨뜨려(선택 기준, 운영 일수, 주문 없는 공장, 이름, 상한, 기존 값 덮어쓰기) 의도한 테스트가 실패함을 확인했다. 새 E2E의 수정 전 실패는 확인하지 못했다. 개발 DB 복사본 보정은 이 검증과 별도로 직접 확인했다(공장 4곳 10억, 마스터 버전 유지, 기존 주문 저장값 유지).
